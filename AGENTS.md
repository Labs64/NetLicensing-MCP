# AGENTS.md

Guidance for AI agents working in this repository. `CLAUDE.md` only imports this file.

## Overview

`netlicensing-mcp` is a FastMCP server exposing the Labs64 NetLicensing REST API as MCP tools and prompts. Transports: **stdio** (default) and **streamable HTTP**. Python ≥ 3.12, async throughout. Requires `mcp[cli]` ≥ 1.21.1: the lowest version that passes the suite (1.7.0 lacks tool titles; 1.10.1, 1.12.4 and 1.16.0–1.21.0 fail to import with the current pydantic). Run the suite against a version before lowering the floor.

## Commands

```bash
pip install -e ".[dev]"                      # dev install (hatch + hatch-vcs for builds)
python -m netlicensing_mcp.server [http]     # stdio (default) / HTTP on $MCP_HOST:$MCP_PORT (127.0.0.1:8000)
mcp dev src/netlicensing_mcp/server.py       # MCP Inspector

pytest tests/ -v [--no-cov]                  # asyncio_mode=auto, coverage on by default
pytest tests/test_tools.py::test_name -v     # one test

# Exact CI checks
ruff check . && ruff format --check .        # `ruff format .` applies
mypy src/ scripts/
python scripts/gen_tools_doc.py --check      # docs in sync; run without --check to regenerate
pip-audit --ignore-vuln CVE-2026-4539 --ignore-vuln CVE-2026-3219

hatch build --target wheel                   # version from git tag (hatch-vcs)
docker build -t ghcr.io/labs64/netlicensing-mcp:latest .
```

CI runs tests on Python 3.12, 3.13, 3.14; lint/format/mypy on 3.14 only.

## Architecture

Layers, top-down:

1. **MCP layer**
   - `app.py`: the single `FastMCP` instance (`instructions=`, `stateless_http=True`), logging, `/health`, annotation presets (`_READONLY`, `_WRITE`, `_UPDATE`, `_DELETE`), response helpers (`_json`, `_wrap_json`, `_wrap_json_token_read`, `_error`, `_confirm_error`, `_list_filter`, …) and the `tool(title=, annotations=)` decorator. The decorator registers a wrapper with the same signature that turns the tool's JSON string into a `CallToolResult`: text unchanged, `structuredContent` = parsed object (`{"result": ...}` for lists/scalars/text), `isError=True` for `{"error": true, ...}`, and the shared `ToolResult` `outputSchema` (no `properties`, to keep `tools/list` small). It returns the original function, so direct calls still return the string. Change registration only here.
   - `mcp_tools/<entity>.py`: the `@tool` wrappers, one module per entity (`products`, `bundles`, `product_modules`, `license_templates`, `licensees`, `licenses`, `tokens`, `transactions`, `payment_methods`, `utilities` incl. `netlicensing_server_info`, `workflows`). Importing registers.
   - `server.py`: entry point (`main()`, console script `netlicensing-mcp`). Imports the `mcp_tools` modules in a fixed order (= `tools/list` order), registers prompts and `/ready`, defines `ApiKeyMiddleware` and `build_http_app()`, and re-exports tools, `mcp`, helpers and `tools/<entity>` modules (`__all__`) so `from netlicensing_mcp.server import …` and patches like `netlicensing_mcp.server.tokens.get_token` keep working.
2. **`tools/<entity>.py`**: build the form payload, call `nl_get/post/put/delete`, run responses through `strip_output_fields`. Shared helpers in `tools/helpers.py`.
3. **`client.py`**: lazy shared `httpx.AsyncClient`, Basic auth, `nl_*` helpers (see Client behaviour).
4. **`errors.py`**, **`responses.py`**, **`redaction.py`**, **`safety.py`**, **`toolsets.py`**: shared modules described below.

Every operation is a thin wrapper named `netlicensing_<action>_<entity>`. It only: (a) maps `""`/`None` to "leave unchanged", (b) calls `tools/<entity>`, (c) turns `NetLicensingError` into a JSON blob with `_error(exc, "<own tool name>")` (a rejected `confirm_token` `ValueError` with `_confirm_error(...)`; `tests/test_error_hints.py` checks each call site passes its own name). Tools return JSON **strings**; `_json()` serializes and applies redaction. Token creates also call `tag_one_time_display()`; token reads use `_wrap_json_token_read()` (applies `redact_token_read()`, masking APIKEY `number` and SHOP `shopURL`, and drops `console_url` for APIKEY/SHOP tokens because the number is the credential).

### Generated files and test fixtures

- `tests/fixtures/tools_snapshot.json` pins every tool's name, title, description, input schema, annotations, order, and the prompts. After an intentional change: `UPDATE_SNAPSHOT=1 pytest tests/test_tool_registry_snapshot.py --no-cov`, then review the diff.
- `docs/TOOLS.md` and the README blocks `<!-- tools:start/end -->`, `<!-- prompts:start/end -->`, the `<!-- count:tools|toolsets|prompts -->` numbers and `"tool_count": N` are generated by `scripts/gen_tools_doc.py` from a registry with every tool enabled. Never edit them by hand; the CI lint job and `tests/test_docs_in_sync.py` run `--check`. Docs use the first docstring paragraph as description and the `Args:` section for parameters.
- Descriptions are sent dedented (`inspect.cleandoc`: `app._add` for tools, `@clean_doc` for prompts); on Python 3.12 FastMCP would send source indentation, which Markdown clients render as code.
- `tests/conftest.py` imports `netlicensing_mcp.server` first (stable registration order) and sets `MCP_TOOLSETS`/`MCP_READ_ONLY` to empty strings (empty = unset; `load_dotenv(override=False)` does not replace them) and `NETLICENSING_BASE_URL`/`MCP_CONSOLE_BASE_URL` to their defaults for the session. Tests needing other values monkeypatch `client.BASE_URL` or the environment, or build their own server (below).

## Conventions

- **Booleans** go upstream as `"true"`/`"false"`; the tools layer converts. MCP signatures: `bool` for required, `bool | None = None` for optional (`None` = leave unchanged), `str = ""` for optional strings (wrapper converts `""` → `None`). LLM clients often send `""` for unspecified fields; keep this pattern.
- **Properties** come as `{"property": [{"name","value"}]}` arrays; the client does not flatten them. `strip_output_fields` removes bulky fields (`logo`) from dict keys and property arrays. Create/update calls deliberately omit `logo` (omission preserves the stored value); never add it to write paths.
- **List scoping**: upstream ignores a bare `?productNumber=X`; scope and paging go in the single `filter` parameter (`filter=productNumber=X;page=0;items=100`). Build it with `scoped_filter()` (rejects `;`/`=` in the scope value and a user filter that sets the scope key). Max page size 100; use `licenses.list_all_licenses()` for everything.
- **Enumerated arguments** (license type, transaction status, time-volume period, licensing model, VAT mode, licensee secret mode, API key role) are checked locally by `tools/helpers.require_one_of`, with the allowed values in the error. Add new enums to the constants in `helpers.py`.

## Client behaviour (`client.py`)

- Non-2xx → `NetLicensingError` with `detail` (unwrapped, de-duplicated `infos.info[].value`), `info_ids`, `retry_after` (numeric `Retry-After`) and `non_json`. Transport failures → `502`/`504`; missing key → `503`.
- `sanitize_detail` cuts stack traces at the first newline/`\tat `, replaces Java class names with `<internal>`, caps at 300 chars; a 5xx that still has internals becomes a fixed message. The full text of 5xx/non-JSON replies goes to the log only. A non-JSON reply (gateway/proxy page) is never echoed: `detail` is fixed text and `non_json=True`.
- `_validated_path` runs on every request: rejects empty or whitespace segments, `/ \ ? # %`, whitespace, control characters and dot-segments (also after repeated percent-decoding and `;` stripping), then percent-encodes each segment. Identifiers cannot reach URL syntax.
- `_apply_client_filter` re-applies `active`, `status`, `tokenType` filters to list results, because Core ignores `active` next to `productNumber` and on license templates, and `status` on transactions. When it drops items it removes `totalitems`/`totalpages` (keeps `hasnext`).
- `base_url_host()` is the only parser of `BASE_URL` (returns `None` instead of raising); use it in server info, hints and `/ready`.
- POST/PUT debug logs pass data through `redact()`; token paths are logged as `/token/****`.

## Error hints (`errors.py`)

`error_hint(exc, tool_name, available=...)` is pure and returns `hint`, `suggested_actions`, `retryable` (and `retry_after_seconds` for 429); `confirmation_hint(tool_name)` does the same for a rejected token. `_error()`/`_confirm_error()` add them after `error`/`status`/`detail`, restricted to registered tools. Mapping follows what NetLicensing returns:

- Missing entity: **`400`** with info id `NotFoundException` (not 404). For `create` tools, "does not exist" naming no known entity is about a referenced value and gets the generic validation hint.
- Duplicate number: `400` `DuplicateEntityException`. Delete blocked by dependents: `400` `IllegalOperationException`. `401` bad credentials, `402` not in plan, `403` key role too low (quotes the role ladder), `429` rate limit.
- A non-JSON `400`/`403` gets the gateway hint, never the role hint. "No active product modules" (404) points to listing/activating modules, not to a missing licensee.
- `retryable` means transient, not idempotent; a failed write's hint names a tool to check state. The `force_cascade` hint appears only for tools in `errors.CASCADE_DELETE_TOOLS` (a test compares it to the registry).
- Hints contain only fixed text, tool names and the base URL **host**; never `detail`, a key or the full URL (tests assert this). Suggestions must be real names from `toolsets.TOOLSETS`.

## Response envelope (`responses.py`)

`wrap(entity, kind, summary=None, suggested_actions=None, raw=None)` and `console_url(kind, number)`.
- Single items become a flat dict: properties promoted, `active` as bool, `console_url` from `MCP_CONSOLE_BASE_URL`, `warningLevelSummary` parsed to an object. Nested `list` groups are kept; MultiFeature validation results are normalized to `features: [{number, name, valid}]` (`feature_results()`).
- Lists become `{"type": "list", "kind", "count", "items": [...]}` (`count` = items in this response) plus `total`, `page`, `total_pages`, `has_more` and (only when `hasnext`) `page_size` from the upstream paging attributes, each only if parseable. `infos` of the configured types are copied to `warnings`, each message once.
- List tools take `page`, `page_size` (default 25, max 100) and `compact` (type, number, name, status, active); `app._list_filter` merges them into `filter`, which is passed as `paging_filter=` to get `next_page_hint`. Payment methods are not paged upstream.
- Every tool accepts `include_raw: bool = False` (adds the sanitized upstream payload under `raw`).

## Redaction (`redaction.py`)

- `redact(payload, fields, mode)` handles dict keys and property arrays. Default fields: `apiKey`, `licenseeSecret`, `nodeSecret`, `password`, `secret`; extend with `MCP_REDACT_FIELDS`. `mode="mask"` keeps first 3 / last 4 characters of values ≥ 16 chars, else `****`; `mode="remove"` drops the field.
- `redact_payment_method()` is an **allowlist**: every property except `number`/`active` becomes the fixed `****` (providers store credentials as custom properties). Applied inside `tools/payment_methods.py`.
- `mask_token_number()` masks token numbers in the delete-token outputs (preview `target`, mismatch error via `safety._SECRET_TARGET_OPS`, success message), since the type is unknown without another call. Display only: confirmation tokens bind to the real number.
- `get_token`, `preview_delete_token`, `delete_token` accept the masked number from `list_tokens`; `tools.tokens.resolve_token_number` matches it against the real list and fails unless exactly one token matches.

## Confirmation tokens (`safety.py`)

- Single-use, 5-minute, in-process tokens bound to: operation, target, owner (scrypt digest of the caller's API key, so tenants cannot use each other's tokens), `force_cascade`, and for updates the normalized change set (`safety.change_set`). Issuing a token never cancels earlier ones. Mismatches (operation/target, `force_cascade`, change set) are rejected **without consuming** the token. Unknown/expired tokens echo only their first 6 characters.
- Updates (`update_product`, `update_license_template`, `update_payment_method`) pass the sensitive arguments as `changes=` to `make_update_preview` and `validate_and_consume`. A preview whose values equal the current ones returns `no_change` and no token; the update tool then applies its non-sensitive fields.
- Delete previews report `requires_force_cascade` and `blocking_dependencies` (products, licensees, modules). Delete tools return JSON (`delete_result`). Only `delete_product`'s preview tool takes `force_cascade`; for other entities call the delete tool without a token and with `force_cascade=true` to get a cascade token. `delete_token` has no cascade option.
- Token creation payloads that carry a credential are tagged one-time-display; the token `number` for APIKEY/SHOP is the credential.

## Toolsets and read-only mode (`toolsets.py`)

`toolsets.TOOLSETS` assigns every tool to exactly one toolset; the decorator raises for a missing tool, so **add every new tool there**. `ToolFilter.from_env()` parses `MCP_TOOLSETS`/`MCP_READ_ONLY` once at `app.py` import; filtered tools are not added to `mcp`, but the decorator still returns the original function. A restriction appends a note to the server instructions (prompts, workflow `suggested_actions` and preview instructions may name unregistered tools; in read-only mode previews are impact analysis only). Tests build servers with `app.new_server(filter)` + `app.register_tools(server, filter)`; `app.active_tool_settings()` reports the state. `netlicensing_server_info` is always registered.

## Workflows (`workflows/`)

Pure modules (no I/O) called by `mcp_tools/workflows.py`.
- `customer_health.build_health`: without live validation the status is never `ok`: it is `unknown` (with `validation_run: false` and a "re-run with `refresh_warning_level=true`" summary) unless something already shows `warning`/`critical`.
- `validation_explain.explain_validation`: a missing `valid` is `None` (unknown), never true; summary counts come from the lists it names; explanations and actions are per licensing model (match on the normalized name, e.g. `PayPerUse`, `NodeLocked`); infos and warnings are de-duplicated.

## API key resolution (`client.api_key_ctx`)

A `ContextVar` defaulting to `NETLICENSING_API_KEY`. In HTTP mode `ApiKeyMiddleware` sets it per request from `X-NetLicensing-API-Key`, then `Authorization: Bearer …` (no query parameter: URLs get logged) and resets it afterwards. FastMCP runs `stateless_http=True` (stateful mode would pin the first request's key to the session), so one deployment serves many tenants. A request without either header gets `401` + `WWW-Authenticate` before any tool runs, even if `NETLICENSING_API_KEY`/`NETLICENSING_ALLOW_DEMO` is set: HTTP mode never uses env or demo credentials. Only stdio or direct calls fall back to sandbox `demo:demo`, and only with `NETLICENSING_ALLOW_DEMO=true`; otherwise `_headers()` raises `503` and `main()` refuses to start stdio.

## First-run check (`netlicensing_server_info`)

Assistants are told (docstring, `app.INSTRUCTIONS` Conventions) to call it first after auth/connection/config errors or when asked whether the setup works. It must **never raise** and **never contain the key** (tests check every branch, including logs).
- Returns `version`, `base_url` (host only), `demo_mode`, `status` (`ok|warning|error`), `auth` (`configured`, `source` = `env|header|demo|none`, `valid`), `checks` (`[{name, ok, detail}]`), `warnings`, `next_steps`, `transport` (`app.active_transport()`, set by `main()` via `app.set_transport()`) and `app.active_tool_settings()`.
- `source`: only `ApiKeyMiddleware` sets the ContextVar, so "set in the copied context" = `header`, default = `env`.
- The check lists one product (`filter=page=0;items=1`) under a 10 s `asyncio.timeout`. `401` → `valid: false`, `error`; `403` → `valid: true`, passing `authentication` + failing `permission`, `warning`; `502`/`504` from `httpx`, or timeout → `valid: null` + failed `reachable`; other errors → `valid: null`, `warning`. `next_steps` reuse `error_hint()` wording with fixed detail text; the "change the key" step is omitted for demo credentials. Demo text: `client.DEMO_MODE_WARNING` (also the throttled log line).

## Prompts

Registered from `server.py` after all tools (prompt modules must not import `server.py`). Each is `@mcp.prompt(...)` with `@clean_doc` directly below. Groups: `prompts/audit.py` (`register_audit_prompts`) and `prompts/setup.py` (`register_setup_prompts`; `Annotated[..., Field(description=...)]` arguments, a `title`, and a shared safety-rules block: confirm writes, preview before delete, no `force_cascade` unless asked, prefer deactivation, never repeat secrets). Arguments and descriptions are listed in `docs/TOOLS.md`.
- Return `mcp.server.fastmcp.prompts.base.UserMessage`, not `mcp.types.PromptMessage` (FastMCP would send a JSON dump).
- Name tools as `` `netlicensing_x(arg="value")` ``. `tests/test_setup_prompts.py` fails on an unregistered tool name, an argument missing from the input schema, or a written-out call missing a required argument; rename prompt calls together with tools. Licensing-model facts must come from the server instructions, tool docstrings or the NetLicensing wiki.
- New prompts/arguments change the snapshot and generated docs (regenerate both); a new `register_*_prompts` must be added to `PROMPT_GROUPS` in `scripts/gen_tools_doc.py`.

## Server instructions

`instructions=` in `app.py` documents the entity hierarchy (Product → ProductModule → LicenseTemplate; Product → Licensee → License; Bundles, Transactions, Tokens, PaymentMethods), licensing models, the response envelope and safety rules (no delete without confirmation; `force_cascade` only on explicit request; prefer deactivation). When a change affects these rules, update the instructions too.

## Configuration (all optional)

| Variable | Meaning |
| --- | --- |
| `NETLICENSING_API_KEY` | Required in stdio unless demo is allowed (empty = fatal at startup). Unused in HTTP mode (key must be in a header). |
| `NETLICENSING_ALLOW_DEMO` | `true` enables sandbox demo mode (stdio only); tags every JSON tool response (incl. error blobs) `"demo_mode": true`, warns every 60 s. Never in production. |
| `NETLICENSING_BASE_URL` | Default `https://go.netlicensing.io/core/v2/rest`. |
| `MCP_TRANSPORT` | `stdio` (default) or `http`; also a positional CLI arg. |
| `MCP_HOST` / `MCP_PORT` | HTTP bind, default `127.0.0.1:8000`. |
| `MCP_VERBOSE` | `true\|1\|yes` or `-v`: debug-log API traffic (redacted) via `app.enable_verbose_logging()`, which keeps `httpx`/`httpcore`/`sse_starlette` at WARNING (they log full URLs, i.e. token numbers and new keys). MCP SDK DEBUG output is not redacted: local debugging only. |
| `MCP_REDACT_FIELDS` | Extra comma-separated field names to redact. |
| `MCP_CONSOLE_BASE_URL` | Base for `console_url`; default `https://ui.netlicensing.io/#`. |
| `MCP_TOOLSETS` | Comma-separated: `products`, `bundles`, `modules`, `templates`, `licensees`, `licenses`, `tokens`, `transactions`, `payments`, `system`, `workflows`, or `all` (default). Unknown names warn and are ignored (also next to `all`); none valid = all. |
| `MCP_READ_ONLY` | `true\|1\|yes` registers only `readOnlyHint=True` tools. Other values except `false\|0\|no` warn and leave it off. Applied after `MCP_TOOLSETS`. |

Logs go to **stderr**; stdout must stay clean in stdio mode.

## Deployment

`deploy/aws/deploy.sh` supports ECS Fargate (production, ALB-fronted) and App Runner (existing accounts only; minimum 1 instance). HTTP mode has two unauthenticated probes, both exempt in `ApiKeyMiddleware`:
- `GET /health`: liveness, always `{"status":"ok","server":"netlicensing-mcp"}` (`app.health_check`). Used by the CloudFormation health checks and `healthcheck.py` (Docker `HEALTHCHECK`); keep the body byte-identical.
- `GET /ready` (`readiness.py`, `register_ready_route()`): `200` `{"status":"ready","server","version","checks":{"app","upstream"}}` when the session manager runs and the API answers, else `503` `{"status":"not_ready","reason",...}`. Upstream probe (`UpstreamProbe`): one credential-less `GET` of the base URL, 3 s timeout, body unread; any HTTP status counts as reachable, transport errors and malformed URLs do not; an unexpected probe exception gives `503` with `probe_error` (only the exception type is logged). The app check fails open if the SDK's private `_session_manager`/`_task_group` are missing and closed when the manager is `None` or not started. Results are cached (success 15 s, failure 5 s); only the host name is reported; an API key is not a readiness criterion. `server.build_http_app()` builds the ASGI app for tests (`tests/test_ready_endpoint.py`).

## Registry metadata and docs examples

- `server.json` is the MCP Registry entry (schema `2025-12-11`, vendored with the Glama schema in `tests/fixtures/registry/`). The release workflow `sed`-replaces `${VERSION}` before `mcp-publisher publish`; `publish-mcp-registry` needs both `publish-pypi` and `publish-docker`. Schema rules: `description` ≤ 100 chars; env vars use `isRequired`/`isSecret`/`format`; packages declare stdio only (no `MCP_TRANSPORT`/`MCP_HOST`/`MCP_PORT`); OCI version lives in the image tag; unknown keys are dropped.
- Name, title and description must agree across `server.json`, Dockerfile `LABEL`s, the `labels:` of `docker/metadata-action` in the release workflow (else it overrides them with GitHub repo values), the README `<!-- mcp-name: ... -->` comment (PyPI ownership check) and the start of the `pyproject.toml` description. `tests/test_registry_metadata.py` checks this.
- `docs/EXAMPLES.md` holds illustrative scenarios; `tests/test_examples_doc.py` fails on unregistered tool names, arguments or prompts there, and checks the README's Cursor install link decodes to the config it shows.
