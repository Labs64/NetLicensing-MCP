# Changelog

Release notes for each version are published on the [GitHub Releases page](https://github.com/Labs64/NetLicensing-MCP/releases).

## Unreleased

### Upgrade notes

- **`structuredContent` changed shape.** Clients that read structured tool output used to get the JSON *string* wrapped as `{"result": "<json string>"}` (the MCP SDK default for tools that return `str`). They now get the parsed object itself, the same JSON as the text content (a result that is not an object comes as `{"result": ...}`), and failed calls set `isError: true` (they used to be sent with `isError: false`). The text content is unchanged.
- **MCP Registry installs now ask for an API key.** `server.json` marks `NETLICENSING_API_KEY` as required (`isRequired: true`; the old `required` key was dropped by the registry). To try the server without an account, run it locally with `NETLICENSING_ALLOW_DEMO=true` (see "No account yet? Demo mode" in the README).
- **`mcp[cli]` ≥ 1.21.1** is now required (was ≥ 1.7.0); see Changed.
- `netlicensing_server_info` makes one read-only API call by default; pass `check_connection=false` for the previous no-call behaviour.
- In the default (non-verbose) mode the log no longer has one `httpx` INFO line per NetLicensing request (`HTTP Request: GET … "HTTP/1.1 200 OK"`); see Security.

### Added

- Every tool has a human-readable `title` (for example "List products", "Create API token"), shown by clients that support tool titles.
- README: a "Connect in 30 seconds" section near the top with one copy-paste snippet per client (Claude Code, VS Code, Cursor, Claude Desktop, Docker) and a demo-mode variant, and a "Client setup" section with the details: Claude Code scopes and remote HTTP (`--transport http --header`), a VS Code `.vscode/mcp.json` that asks for the key (`inputs`, `password: true`) and a remote HTTP entry, a Cursor install link (`cursor://anysphere.cursor-deeplink/mcp/install`) and `${env:...}` key, Claude Desktop config paths for macOS, Windows and Linux, JetBrains (Copilot `mcp.json` with `servers`) and other clients.
- `docs/EXAMPLES.md`: six vendor scenarios (first run in demo mode, launching a subscription product, a support ticket, a renewal sweep, a customer migration, offboarding) with example prompts and the tool calls they trigger, marked as illustrative. Linked from the README. `tests/test_examples_doc.py` checks that every tool, argument and prompt named there is registered.
- Six setup and troubleshooting prompt templates next to the five audit prompts (`prompts/setup.py`, `register_setup_prompts`): `setup_subscription_product` (`product_name`, `plans`), `setup_trial` (`product_number`, `trial_days`, default 14), `onboard_customer` (`customer_name`, `product_number`, optional `licensee_number`, `module_number`, `license_template_number`), `migrate_customer` (`from_licensee_number`, `to_licensee_number`), `troubleshoot_validation` (`licensee_number`, optional `product_number`, `product_module_number`) and `issue_api_key` (`purpose`). Each walks the assistant through the task with the exact tool names and arguments, previews before changes, asks for confirmation before writes, never deletes or cascades on its own, and shows a new API key or checkout URL only once. Prompt arguments carry descriptions and the prompts have titles. The server instructions mention them. A test checks that every tool and argument a prompt names exists in the tool registry.
- `GET /ready` readiness endpoint (HTTP mode, no API key needed): `200` `{"status": "ready", "server", "version", "checks": {"app", "upstream"}}` when the MCP endpoint is running and the NetLicensing API answers, otherwise `503` with `"status": "not_ready"` and a `reason`. The upstream check is one unauthenticated `GET` of `NETLICENSING_BASE_URL` (3-second timeout; any HTTP status counts as reachable; timeouts, connection and other transport/protocol errors, and a malformed URL count as unreachable), cached for 15 seconds (a failure for 5 seconds). If the check itself fails unexpectedly, `/ready` answers `503` with error `probe_error` and reason `readiness check failed (probe_error)` instead of a `500`. The reply names only the API's host name, never a key or the upstream response. `GET /health` (liveness) is unchanged and stays the load balancer / container health check; `deploy/aws/README.md` explains which probe to use for what.
- `netlicensing_server_info` is now a first-run check. Besides `version`, `base_url` and `demo_mode` it returns `status` (`ok` / `warning` / `error`), `auth` (`configured`, `source`: `env` / `header` / `demo` / `none`, `valid`: `true` / `false` / `null`; never the key), `checks` (`[{name, ok, detail}]`), `warnings`, plain-language `next_steps`, `transport` (`stdio` / `http`), `toolsets`, `read_only` and `tool_count`. By default it makes one read-only API call (lists one product, 10-second timeout) to check that NetLicensing is reachable and accepts the key (`401` → `valid: false`; `403` → `valid: true` with a failed `permission` check and a warning, since NetLicensing answers `403` to a valid key whose role does not allow the operation; network error or timeout → `valid: null` and a failed `reachable` check); the new optional `check_connection=false` skips the call. Its description tells assistants to call it first when something fails. The README has a new "First run" section.
- The server instructions tell assistants to run `netlicensing_server_info` first when a tool fails with an authentication, connection or configuration error, or when the user asks whether the setup works.
- Paging hints on list results: besides `count` (items in this response) a list result now carries the paging data NetLicensing reports — `total`, `page` (0-based), `total_pages`, `has_more` and, when there is a next page, `page_size`. Paged list tools add `next_page_hint`, the JSON-quoted `filter` value that fetches the next page. Fields the API does not send are left out; payment methods, licensing models, license types and countries are not paged.
- `netlicensing_list_bundles` accepts an optional `filter` (e.g. `active=true`, or `page=1;items=100` for the next page), like the other list tools.
- Error results now say what to do next: besides `error`, `status` and `detail` they carry `hint` (one actionable sentence), `suggested_actions` (names of registered tools, e.g. `netlicensing_list_licensees` when a licensee was not found) and `retryable`. `retryable` is `true` for transient failures: `429` (with `retry_after_seconds` from `Retry-After`), NetLicensing server errors (`500` and other `5xx`), an unreachable API (`502`) and timeouts (`504`); it is `false` for the `503` this server returns when no API key is configured, and for every other `4xx`. It means "may succeed later", not "safe to repeat": a failed write may already have been applied, and its hint names a tool to check the state with first. A missing entity (NetLicensing answers `400` `NotFoundException`), a duplicate number, a delete blocked by dependents, bad credentials, a too-low key role (with the role ladder from the NetLicensing API Conventions) and a feature outside the pricing plan each get their own hint. Rejected confirmation tokens (errors without `status`) point at the matching `preview_*` tool. Hints never contain the API key, the `detail` text or more of the base URL than its host.
- `MCP_TOOLSETS` (comma list of toolsets: `products`, `bundles`, `modules`, `templates`, `licensees`, `licenses`, `tokens`, `transactions`, `payments`, `system`, `workflows`; default `all`) and `MCP_READ_ONLY=true` (only tools annotated read-only) shrink the registered tool list. `netlicensing_server_info` is always registered, and the server instructions mention an active restriction (including that prompts, workflow `suggested_actions` and preview instructions may name tools that are not registered, and that previews are impact analysis only in read-only mode). Unknown toolset names are logged as a warning and ignored, also next to `all`; an `MCP_READ_ONLY` value other than `true`/`1`/`yes`/`false`/`0`/`no` logs a warning that read-only mode is off. Without these variables all 61 tools are registered as before.
- Structured tool output: every tool result now carries `structuredContent` (the same JSON object as the text content; non-object results as `{"result": ...}`), every tool declares an `outputSchema`, and error results set `isError`. The text content is unchanged. See Upgrade notes.
- `docs/TOOLS.md`: a reference of every tool (title, read-only / write / destructive badge, annotations, description and parameters with type, required flag, default and description) and every prompt (with its arguments), generated from the server's registry by `scripts/gen_tools_doc.py`. The README's tool tables (folded per toolset), prompt tables and its tool and prompt counts are generated by the same script; the README also lists an example invocation per prompt. `python scripts/gen_tools_doc.py --check` (also a CI step and a test) fails when they are out of date.
- Deploy lint workflow (`.github/workflows/netlicensing-deploy-lint.yml`), run on pushes and pull requests to `master` that touch `deploy/**`, `Dockerfile`, `healthcheck.py`, `pyproject.toml`, `uv.lock`, `src/**` or the workflow itself (the image is built from the package and its lock file): `cfn-lint` (pinned to 1.61.0) on `deploy/aws/*.yaml`, `shellcheck deploy/aws/deploy.sh`, `deploy.sh help` without AWS credentials, and a Docker build of the release wheel that is started in HTTP mode and must turn healthy, answer `/health` and reject `POST /mcp` without a key with `401`. The App Runner template ignores cfn-lint's `W3697` (App Runner is in maintenance mode) in its two App Runner resources' `Metadata`; CONTRIBUTING.md shows how to run the checks locally.
- `tests/test_http_e2e.py`: end-to-end tests over the real HTTP app (`build_http_app()`) with a fake NetLicensing API: `/health`, `/ready` (upstream reachable and unreachable), `401` + `WWW-Authenticate` without a key, `initialize` with the `X-NetLicensing-API-Key` header or a Bearer token, `tools/list` (61 tools), a `tools/call` returning the response envelope, and per-request API keys, including two concurrent requests with different keys.
- `tests/test_registry_metadata.py`: validates `server.json` (after the release workflow's `${VERSION}` substitution) against the MCP Registry schema and `glama.json` against Glama's schema (both vendored in `tests/fixtures/registry/`), and checks that the server name, title and description agree across `server.json`, the Dockerfile labels, the release workflow, the README and `pyproject.toml`.
- A golden snapshot of the tool and prompt registry (`tests/fixtures/tools_snapshot.json`, checked by `tests/test_tool_registry_snapshot.py`; regenerate with `UPDATE_SNAPSHOT=1`). `tests/conftest.py` registers the tools in their canonical order before any test module is imported and ignores `MCP_TOOLSETS` / `MCP_READ_ONLY` from the developer's shell or `.env` file for the test session.
- PyPI keywords `mcp-server` and `licensing-as-a-service`; classifiers `Topic :: Office/Business` and `Topic :: Scientific/Engineering :: Artificial Intelligence`. The classifiers `Typing :: Typed` (the package ships no `py.typed`) and `Topic :: Software Development :: Libraries` (it is a server, not a library) are removed.

### Changed

- The update tools (`netlicensing_update_*`) and `netlicensing_transfer_licenses` are annotated `destructiveHint: false` (was `true`): they change data but do not delete it. Delete tools stay `destructiveHint: true`.
- The minimum MCP SDK is `mcp[cli]>=1.21.1` (was `>=1.7.0`): the lowest version tested that passes the full test suite in a fresh install (on Python 3.12 and 3.14). Every older release tried fails: `mcp` 1.7.0 has no tool titles, and 1.10.1, 1.12.4 and 1.16.0 to 1.21.0 fail to import with the current pydantic (2.14).
- Prompt descriptions say more about what each prompt does (for example that `audit_expiry` generates renewal URLs and `setup_trial` creates a free, automatic TIMEVOLUME trial template and a FEATURE full-version template). Prompt names and arguments are unchanged.
- `netlicensing_server_info` makes one API call by default (see Added); pass `check_connection=false` for the previous no-call behaviour.
- AWS deployment guide (`deploy/aws/README.md`) rewritten as a step-by-step path: ECS Fargate behind an Application Load Balancer, first over plain HTTP for a sandbox test, then HTTPS with an ACM certificate and a DNS CNAME for your own domain, verification with `curl`, and client setup. App Runner is documented only for existing App Runner customers, since AWS has closed it to new customers. The README's AWS section follows it.
- `deploy.sh fargate` warns when no `--certificate-arn` is given (plain HTTP sends clients' API keys unencrypted). `deploy.sh help` works without the AWS CLI or credentials.
- The Fargate stack no longer has an `McpEndpointHttps` output with the load balancer's `…elb.amazonaws.com` name, for which a certificate never validates; it outputs `CertificateInUse` instead, and the plain-HTTP endpoint output says it is for testing only.
- Internal: `server.py` is split into `app.py` (the `FastMCP` instance, instructions, helpers and the `tool()` decorator) and one `mcp_tools/<entity>.py` module per entity. `netlicensing_mcp.server` still re-exports every tool function and helper, and the entry points (`netlicensing-mcp`, `python -m netlicensing_mcp.server`, `mcp dev src/netlicensing_mcp/server.py`) are unchanged.

### Fixed

- `console_url` deep links pointed at Console paths that do not exist (e.g. `…/#/licensees/I001`). They now use the Console's routes: `products/<number>/edit`, `products/<product>/modules/<number>/edit`, `customers/<number>/edit`, `customers/<licensee>/licenses/<number>/edit` and `bundles/<number>/edit`. License templates, transactions, tokens and payment methods have no Console page of their own and get no `console_url`; neither does a module or license whose parent number is missing.
- `initialize` reported the MCP SDK version as `serverInfo.version`; it now reports the netlicensing-mcp version.
- The audit prompts (`audit_full`, `audit_customer`, `audit_expiry`, `audit_cleanup`, `audit_anomaly`) were delivered to clients as a JSON dump of the message object (`{"role": "user", "content": {"type": "text", "text": "..."}}` with escaped newlines) instead of the prompt text. They now send the prompt text itself; the text is unchanged.
- On Python 3.12, tool and prompt descriptions were sent with the docstring's source indentation, which Markdown clients render as code blocks. They are now dedented (Python 3.13 and later already stripped it); the text is unchanged.
- The Fargate template's `UseSpot=true` had no effect: the service set `LaunchType: FARGATE`, which overrides capacity providers. It now uses a capacity provider strategy (`FARGATE_SPOT` or `FARGATE`).
- App Runner template and `deploy.sh apprunner`: the minimum instance count defaults to 1 and must be at least 1 (App Runner has no scale-to-zero, which the guide used to promise); the service is named after the stack; `ImageUri` has no GHCR default (App Runner pulls only from ECR). `deploy.sh mirror` creates the ECR repository named in `--ecr-repo` (it always created `netlicensing-mcp`), checks the argument's format and that Docker is installed, and copies the `linux/amd64` image (an Apple Silicon Mac would otherwise push the arm64 variant).
- `server.json` did not pass the MCP Registry schema: its `description` was longer than the 100 characters allowed, and with the declared `2025-09-29` schema the OCI package also needed a `version`. It now targets the current schema `2025-12-11`, uses `isRequired` instead of `required` for environment variables (the schema has no `required` there, and the registry drops unknown keys: the published 1.0.1 entry has no `required`, `homepage` or `license`), so `NETLICENSING_API_KEY` is now marked required for registry clients; it also adds `format: boolean` to the boolean variables and a `runtimeHint` (`uvx`, `docker`) per package, removes `MCP_TRANSPORT`, `MCP_HOST` and `MCP_PORT` from both packages (they declare the stdio transport, which `MCP_TRANSPORT=http` would break), and drops the `homepage` and `license` keys, which the schema does not define (`websiteUrl` and `repository` stay). The `${VERSION}` placeholders and their substitution in the release workflow are unchanged.
- The release workflow published to the MCP Registry in parallel with the Docker image build, but the registry checks that the OCI image named in `server.json` exists. `publish-mcp-registry` now waits for `publish-docker` as well as `publish-pypi`.
- The published Docker image's title, description and url labels came from the GitHub repository (set by `docker/metadata-action`), not from the Dockerfile. The release workflow now passes the Dockerfile's values; the image title is "NetLicensing MCP Server" and its description matches `server.json`.
- README: the Docker HTTP example now sets `MCP_HOST=0.0.0.0`; without it the server listens on `127.0.0.1` inside the container and the published port does not answer. The Claude Desktop "HTTP mode" example, which started a detached container as if it were a stdio server, is removed (Claude Desktop's documented custom-connector flow takes a URL and has no custom headers; use stdio). The VS Code section no longer refers to a `.vscode/mcp.json` in the repository (it was deleted), and the JetBrains section shows Copilot's `servers` format instead of pointing to the `mcpServers` block. Troubleshooting lists Claude Desktop's log folders as documented (`~/Library/Logs/Claude`, `%APPDATA%\Claude\logs`, `~/.config/Claude/logs`), adding Linux.
- The hint for a delete blocked by dependents no longer suggests `force_cascade` or deactivation (`active=false`) for `netlicensing_delete_token`, which has neither; it mentions them only when the tool or an update tool for the entity offers them.
- The GitHub pull-request labeler now labels changes to `app.py`, `mcp_tools/`, `workflows/`, `toolsets.py`, `errors.py`, `readiness.py`, `safety.py`, `responses.py` and `redaction.py` as `mcp`, and to `uv.lock` as `dependencies`.

### Security

- Deleting a token no longer echoes the token number in full. For APIKEY tokens the number is the API key, for SHOP tokens the checkout credential; `get_token` / `list_tokens` already masked it, but the delete preview's `target` (`netlicensing_preview_delete_token`, and `netlicensing_delete_token` without `confirm_token`), the delete message (`Token <number> deleted (HTTP …)`) and the error for a confirmation token issued for another target showed it. They now show the read-path mask (`a1b****7890`; numbers under 16 characters become `****`) for every token type, since the type is not known on the delete and error paths without another API call. The confirmation token is still bound to the real token number. The `issue_api_key` prompt's revoke step now says these results show the key only masked.
- Logs no longer contain full token numbers. `httpx` logged every request URL at INFO, the default level (`HTTP Request: GET https://…/token/<number> …`), so reading, previewing or deleting an APIKEY or SHOP token wrote the key to stderr; in verbose mode `httpcore` added request details and `sse_starlette` logged every HTTP-mode response chunk, including a key shown once by `create_api_token`. These three loggers are now held at `WARNING` in every mode, verbose included, so the default mode no longer logs a line per NetLicensing request. The server's own request lines (`GET …/token/**** …`) still show requests in verbose mode. The README and SECURITY.md now say that verbose mode also enables the MCP SDK's own DEBUG output, which is not redacted, and is for local debugging only.
- The errors for an unknown or expired `confirm_token` repeat only its first 6 characters (`'CONF-A…'`) instead of the whole value, in case a caller passes a secret in that argument.
